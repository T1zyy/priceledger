# PriceLedger

Сервис хранит закупочные цены и правила наценки по категориям. Стоимость задаётся в копейках, наценка — в базисных пунктах (2500 означает 25%). Правило применяется ко всем товарам категории. Целочисленная формула `(cost × (10000 + markup) + 5000) / 10000` округляет половину копейки вверх. Допустимая закупочная цена от 1 до 10¹² копеек, наценка от 0 до 100000 базисных пунктов.

## Запуск и проверка

Для запуска нужен Docker Compose v2. Все команды выполняются из корня репозитория.

```sh
make up           # запустить локальный стенд
make verify       # интеграционные тесты и сквозная проверка HTTP, gRPC и Kafka
make down         # остановить стенд, сохранив данные
```

## Попробовать

После `make up` выполните:

```sh
curl -i -X PUT localhost:18080/v1/rules/dairy -H 'Content-Type: application/json' -d '{"markup_bps":2000}'
curl -sS -X PUT localhost:18080/v1/products/milk -H 'Content-Type: application/json' -d '{"category":"dairy","cost_kopecks":10000}'
curl -i -X PUT localhost:18080/v1/rules/dairy -H 'Content-Type: application/json' -d '{"markup_bps":2500}'
curl -sS 'localhost:18080/v1/prices/milk/history?after=0'
curl -sS localhost:18080/v1/prices/milk
```

Первый вызов создаёт правило. Регистрация товара возвращает 12000 копеек и версию 1. После смены правила история содержит вторую версию с ценой 12500 копеек. Повтор неизменившегося ввода сохраняет номер версии. История выдаётся по возрастанию версии блоками до 100 записей, параметр `after` исключает уже полученную версию. При переносе товара новое правило выбирается по переданной категории.

При установленном grpcurl из корня проекта:

```sh
grpcurl -plaintext -import-path api -proto pricing.proto -d '{"sku":"milk"}' localhost:19090 commerce.v1.Pricing/GetPrice
```

## Доставка изменений

Текущая цена, снимок истории и запись outbox фиксируются одной транзакцией. Воркер захватывает строку outbox через `FOR UPDATE SKIP LOCKED`, публикует событие в `prices.changed` с ключом SKU и отмечает запись отправленной после подтверждения Kafka. При недоступном брокере транзакция откатывается, запись остаётся в очереди. Сбой между публикацией и фиксацией допускает повтор сообщения.

Событие содержит `event_id` вида `milk:2`, тип `price.changed` и снимок цены. Consumer отмечает обработанный идентификатор в PostgreSQL и записывает актуальный снимок в Redis. Транзакция с отметкой завершается после успешной записи кэша. При повторе после сбоя Redis принимает только такую же или более новую версию. Ошибочные конверты фиксируются в `pricing.rejected`. Offset Kafka подтверждается после обработки.

Чтение текущей цены использует Redis с TTL 60 секунд. При промахе или ошибке Redis данные читаются из PostgreSQL. После изменения правил кэш обновляется асинхронно, поэтому немедленный GET может показать предыдущую версию. Результат записи и история читаются из основной БД. При большом числе товаров изменения правил держат блокировки до окончания пересчёта всей категории — это граница выбранной модели.
